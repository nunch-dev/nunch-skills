# Ready to Fight domain lenses

세션 시작 시 대상에 맞는 절 하나를 선택하고, 세 필수 범주를 사용자에게 공개합니다. 각 범주는 `근거 있음`, `반박됨`, `미결`, `해당 없음(이유)` 중 하나로 추적합니다. 사용자가 항목을 추가하거나 잘못된 routing을 고칠 수 있지만, 필수 범주를 임의로 삭제하거나 말없이 건너뛰어서는 안 됩니다.

여러 lens가 겹치면 지금 결정에 가장 직접적인 lens부터 한 번에 하나씩 적용합니다. 선택이 결론을 바꿀 만큼 모호하면 반론보다 routing 질문 하나를 먼저 합니다.

## Deep Interview 후속 검증

| 필수 범주 | 검증할 내용 | 결정 중요 미결의 예 |
| --- | --- | --- |
| 의도·결정 일관성 | Stable Intent, 확정된 선택, 현재 제안이 서로 충돌하지 않는지 | 제안이 승인된 핵심 방향을 바꾸지만 사용자가 그 변경을 확인하지 않음 |
| acceptance criteria·비목표 | 성공 조건이 관찰 가능하며 비목표·승인 범위를 침범하지 않는지 | 완료 판정에 필요한 acceptance criterion이 빠짐 |
| 근거·출처와 반환 gate | 결정 근거의 provenance가 충분한지, finding이 의도·핵심 결정·acceptance criterion을 바꾸는지 | 핵심 방향 변경이 발견돼 Deep Interview의 질문·Restate·재승인이 필요함 |

핵심 방향을 바꾸는 finding이면 즉시 RTF loop를 멈추고 변경 변수 하나를 묻는 질문 정확히 하나만 반환합니다. 구현·근거·테스트 세부의 finding은 RTF 안에 남깁니다.

## 서비스 기획

| 필수 범주 | 검증할 내용 | 결정 중요 미결의 예 |
| --- | --- | --- |
| 사용자·문제·대안 | 실제 대상 사용자와 문제, 현재 대안, 전환 이유가 근거로 연결되는지 | 문제가 반복되는지 또는 기존 대안보다 나은 이유를 확인할 수 없음 |
| 성공·guardrail·실험 | 성공 지표, 부작용 guardrail, 가장 작은 반증 가능 실험이 있는지 | 성공과 피해를 구분할 측정 방법이 없음 |
| 위험·제약과 최신 외부 근거 | 운영·정책·시장·가격·경쟁 제약과 현재 근거가 유효한지 | 결정에 중요한 현재 사실의 공식 출처가 상충하거나 재확인에 실패함 |

결정에 중요한 외부 사실은 공식·1차 출처부터 조사하고 직접 링크, `observed_at`, 반대 근거, 한계를 남깁니다. 최종 종합 직전에 변동 가능 사실을 현재 run에서 다시 확인합니다.

## FE·BE 개발 검증

| 필수 범주 | 검증할 내용 | 결정 중요 미결의 예 |
| --- | --- | --- |
| 관찰 행동·인터페이스·데이터 불변식 | 사용자에게 보이는 동작, FE↔BE 계약, 상태 전이와 보존돼야 할 데이터 규칙이 일치하는지 | 오류·경계 입력에서 기대 응답이나 데이터 규칙이 정의되지 않음 |
| 실패·보안·성능·관측성 | 실패 모드, 권한·신뢰 경계, 성능 예산, 로그·메트릭·추적 신호가 있는지 | 실패를 탐지하거나 안전하게 복구할 방법이 없음 |
| 테스트·회귀·rollback | 정상·실패 경로 검증, 회귀 범위, 배포 중단·rollback 조건이 있는지 | 핵심 동작을 증명할 테스트나 되돌릴 기준이 없음 |

FE와 BE가 함께 있으면 같은 세 범주에서 양쪽 계약을 연결해 검증합니다. 모바일·태블릿 동작은 사용자가 별도로 요청했거나 결정 조건에 명시됐을 때만 포함합니다.
