# 한글 커밋 컨벤션

저장소나 사용자가 다른 규칙을 지정하지 않았을 때 적용합니다.

## 기본 원칙

- 요약과 본문은 한글로 작성합니다.
- 타입 식별자는 영문으로 유지합니다.
- 이모지는 기본적으로 사용하지 않습니다. 사용자가 별도로 요청한 경우에만 타입에 맞는 이모지를 제목 맨 앞에 추가합니다.
- 제목은 전체 50자 이내로 작성하고, 구체적인 동작을 `추가`, `수정`, `제거`, `개선`처럼 분명하게 표현합니다.
- 본문은 제목만으로 이유나 중요한 세부 사항을 설명하기 어려울 때만 작성합니다.
- 본문은 72자 단위로 줄바꿈하고, 여러 변경은 실제 Markdown bullet이 되도록 줄을 나눕니다. 문자열 `\n`을 그대로 넣지 않습니다.

## 제목 형식

일반 저장소:

```text
[<타입>]: <한글 요약>
```

모노레포의 특정 서비스:

```text
(<서비스명>) [<타입>]: <한글 요약>
```

모노레포 전역 설정:

```text
(root) [<타입>]: <한글 요약>
```

분리할 수 없는 여러 서비스 변경:

```text
(api, admin) [<타입>]: <한글 요약>
```

서비스별 변경을 독립적으로 commit할 수 있으면 여러 서비스를 병기하지 말고 나눕니다.

## 타입

| 타입 | 용도 | 요청 시 이모지 |
| --- | --- | --- |
| `feat` | 새로운 기능 | ✨ |
| `bug` | 일반 버그 수정 | 🐛 |
| `hotfix` | 긴급 버그 수정 | 🚑 |
| `setting` | 설정 파일 변경 | ⚙️ |
| `init` | 프로젝트 초기 설정 | 🎉 |
| `style` | CSS와 UI 스타일 | 💄 |
| `refact` | 동작을 유지하는 리팩터링 | ♻️ |
| `docs` | 문서 작성과 수정 | 📝 |
| `test` | 독립적인 테스트 변경 | ✅ |
| `performance` | 성능 개선 | ⚡ |
| `deps` | 패키지와 의존성 변경 | 📦 |
| `build` | 빌드 시스템 변경 | 🔧 |
| `trash` | 파일 삭제 | 🗑️ |

구현과 직접 연결된 테스트는 구현 타입의 commit에 함께 둡니다. `test`는 테스트 자체가 독립적인 작업일 때 사용합니다.

## 예시

```text
(admin) [feat]: 엑셀 파일 업로드 기능 추가

- 드래그 앤 드롭 업로드 지원
- 엑셀 파일 파싱과 진행 상태 표시
```

사용자가 이모지를 요청한 경우:

```text
✨ (admin) [feat]: 엑셀 파일 업로드 기능 추가
```
