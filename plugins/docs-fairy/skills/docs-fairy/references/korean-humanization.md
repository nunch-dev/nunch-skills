# 한국어 윤문 연동

`docs-fairy`가 만든 한국어 초안의 AI 문체와 번역투를 줄이는 설치 조건부 자동 finishing pass입니다. `humanize-korean` 스킬이 현재 주입된 스킬 목록에서 실제로 호출 가능할 때 적용합니다. 저장소에 플러그인 소스 폴더가 있다는 이유로 설치됐다고 판단하지 않으며, 플러그인 설치나 연결을 이 작업의 일부로 만들지 않습니다.

## 적용 시점

다음 조건을 모두 만족할 때 적용합니다.

- 새 문서를 작성했거나 기존 문서의 한국어 본문을 실질적으로 재작성했다.
- 번역 결과를 포함해 윤문할 자연어 산문이 있다.
- `docs-fairy`가 사실, 문서 유형, 정보 구조, 예제와 링크를 먼저 검증했다.
- 사용자가 원문 표현의 verbatim 보존을 요구하지 않았다.

`SYNC`·`AUDIT`의 진단 보고, 문서 위치 안내, 지목된 오타 수정처럼 새 산문을 만들지 않는 작업에는 적용하지 않습니다. `humanize-korean`이 없거나 실행할 수 없으면 검증된 초안을 그대로 사용하고, 설치를 권하거나 실패로 처리하지 않습니다.

## 역할 경계

`docs-fairy`가 문서의 사실과 구조를 소유합니다. `humanize-korean`에는 자연어 산문 문단의 문체만 맡기고 다음 요소는 윤문 대상에서 제외합니다.

- YAML frontmatter, 헤딩 계층과 anchor
- 코드 fence, inline code, Mermaid와 HTML
- 명령어, 옵션, API·CLI 이름, 환경 변수, 코드 식별자
- 파일 경로, URL과 링크 대상
- 표의 구조와 정확한 값, 번호가 있는 절차의 순서
- 수치, 날짜, 버전, 고유명사, 직접 인용

목록 항목이나 표 안의 설명을 윤문해야 한다면 마커·행·열 구조를 보존한 채 자연어 부분만 처리합니다. 보호 요소를 안정적으로 분리할 수 없으면 그 구간은 건드리지 않습니다.

## 실행과 채택

1. 검증을 마친 초안을 보존하고, 윤문할 산문만 안정적인 구분자와 함께 임시 입력 파일로 분리합니다.
2. 대상 저장소 밖의 임시 디렉터리를 `humanize-korean` 작업 cwd로 사용합니다. 해당 스킬이 만드는 `_workspace/`와 중간 산출물을 프로젝트에 남기지 않습니다.
3. 장르는 전달하지 않고 `humanize-korean`이 입력에서 추정하게 하며, 강도는 `기본`으로 전달합니다. 사용자가 장르나 강도를 명시했으면 그 값을 우선합니다. 경로 선택과 변경률·의미 보존 게이트는 그 스킬의 현재 계약을 그대로 따릅니다.
4. 통과한 `final.md`에서 윤문 본문만 원래 문단 위치에 되돌립니다. `<!-- HUMANIZE-SUMMARY -->` 블록과 humanize 중간 산출물은 대상 문서에 넣지 않습니다.
5. 윤문 전후를 다시 비교해 보호 요소, 사실, 주장, 절차 순서가 같은지 확인합니다. 하나라도 달라졌으면 해당 문단을 초안으로 롤백합니다.
6. `humanize-korean`이 중단·보류 판정을 내리거나 검증 결과를 확인할 수 없으면 윤문본을 채택하지 않고 검증된 초안을 유지합니다.
7. 결과 보고에 필요한 경로·변경률·등급 또는 게이트 결과를 보존한 뒤 임시 윤문 디렉터리를 정리합니다.

수정 결과 보고에는 윤문을 적용했을 때만 `humanize-korean`의 경로, 최종 변경률, 등급 또는 게이트 결과를 한 줄로 포함합니다. 윤문 workflow의 상세 summary는 문서 본문에 복사하지 않습니다.
