코드베이스와 프로젝트 이력을 근거로 문서를 생성·기록·동기화·개선하고 Starlight 기반 문서 사이트를 구축·통합하는 documentation 스킬입니다. 현재 동작은 코드에서, 변경 시점은 git 이력에서, 결정 이유는 ADR·이슈·사용자 설명에서 검증합니다. 명시된 수정은 바로 실행하고 조사 중 발견한 변경은 진단·승인 후 처리합니다.

## 사용 시점

- README, 아키텍처/설계 문서, API·CLI 레퍼런스, CHANGELOG, 런북을 새로 작성할 때
- ADR·의사결정 로그·프로젝트 히스토리·사고 기록으로 프로젝트 맥락을 보존할 때 (`RECORD`)
- 코드 변경 후 낡은 문서를 찾을 때 (git diff 기반 `SYNC`) 또는 문서 전체를 점검할 때 (`AUDIT`)
- 기존 문서의 구조·명확성을 개선하거나 오타를 수정할 때
- 문서를 번역하거나, 문서 위치를 찾아 안내할 때
- Starlight 문서 사이트를 새로 만들거나 기존 사이트에 문서를 통합할 때

문서가 아닌 것이 대상이면 사용하지 않습니다 — 코드 주석·커밋 메시지·PR 설명 작성, 외부 공식 문서 조회, 스펙 기반 코드 생성, 코드 디버깅.

## 사용 예

```text
$docs-fairy 이 플러그인에 포함된 각 스킬의 용도와 사용 시점을 문서로 정리해줘
```

## 핵심 계약

- **권한 우선순위**: 사용자가 대상과 변경을 명확히 지정했으면 바로 수정합니다. SYNC·AUDIT·IMPROVE에서 새로 발견한 항목과 최초 요청에 없던 삭제·전면 재작성·대규모 구조 변경·rename은 근거와 영향을 먼저 보고하고 승인받습니다.
- **누락 분류**: 누락은 필수 누락, 선택적 보강, 비대상으로 나눕니다. 독자·기존 문서 범위·공개 인터페이스 근거가 없는 신규 기능을 자동으로 필수 누락으로 만들지 않습니다.
- **근거 기반 작성**: 명령·옵션·경로는 코드에서, 변경 이력은 git 기록에서, 결정 이유는 기존 ADR·이슈·회의 기록·사용자 설명에서 확인합니다. 코드만 보고 과거 의도를 추정하지 않습니다.
- **기록 보존**: ADR은 결정 하나만 다루고, 바뀐 결정은 기존 기록을 지우지 않고 `Superseded` 상태와 새 ADR 링크로 남깁니다. 프로젝트 히스토리는 커밋 나열 대신 검증 가능한 전환점으로 묶습니다.
- **보고에 표 발췌**: 결과 보고에는 핵심 표(명령어 표 등)를 산문 요약 대신 그대로 발췌해 보여줍니다.

## 문서 규칙

- 언어는 사용자 지정, 프로젝트의 기존 관례, 한국어 순으로 선택합니다. 기존 파일명과 `README.md` 같은 생태계 표준명을 보존하고 일반 신규 문서에만 영어 kebab-case를 사용합니다.
- 생태계 표준 파일의 번역은 `README-ko.md`처럼 locale suffix를 사용하고 일반 문서는 locale 디렉터리로 구분합니다. rename은 명시 요청 또는 영향 진단 후 승인된 경우에만 수행합니다.
- 새 문서 세트나 사이트 구조에는 필요한 경우 Diátaxis를 적용하고, Good Docs의 작성 패턴을 tutorial·how-to·reference·explanation에 맞춰 사용합니다. ADR·프로젝트 히스토리·사고 기록에는 고유 기록 형식을 우선합니다.
- 한국어 문서를 새로 쓰거나 실질적으로 재작성할 때 실행 가능한 `humanize-korean`이 있으면 자동으로 적용합니다. 사용자가 허용한 로컬 사본을 먼저 확인할 수 있으며 후보의 경로·버전이 아니라 전처리기와 gate의 실행 사전 점검으로 선택합니다. 정확값이 바뀌거나 검증에 실패하면 초안을 유지합니다.
- 간결함 우선, 예제 중심. 명령·옵션이 여러 개면 마크다운 표로 정리하고, 함정·제약은 별도 주의사항 섹션에 목록으로 모읍니다.

## 문서 사이트

기본 프레임워크는 Starlight입니다. 기존 `docs/`가 원본 문서 위치면 덮어쓰지 않고 충돌 없는 사이트 경로를 선택합니다. Mermaid·내부 링크 검증·공식 i18n을 사용하며 정본과 동기화 방식, 루트 품질 게이트 참여 여부를 확인합니다. 프로덕션 build와 preview 브라우저 검수 없이 완료를 선언하지 않습니다. 배포(CI) 설정은 기본 범위가 아닙니다.
