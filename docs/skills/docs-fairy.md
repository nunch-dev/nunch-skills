# docs-fairy

## 개요

코드베이스를 근거로 문서를 생성·동기화·개선하고 Starlight 기반 문서 사이트를 구축·통합하는 documentation 스킬입니다. 코드에서 검증한 사실만 문서에 적고, 기존 문서 수정은 진단 보고 → 승인 → 수정의 계약을 따릅니다.

## 사용 시점

- README, 아키텍처/설계 문서, API·CLI 레퍼런스, CHANGELOG, 런북을 새로 작성할 때
- 코드 변경 후 낡은 문서를 찾을 때 (git diff 기반 `SYNC`) 또는 문서 전체를 점검할 때 (`AUDIT`)
- 기존 문서의 구조·명확성을 개선하거나 오타를 수정할 때
- 문서를 번역하거나, 문서 위치를 찾아 안내할 때
- Starlight 문서 사이트를 새로 만들거나 기존 사이트에 문서를 통합할 때

문서가 아닌 것이 대상이면 사용하지 않습니다 — 코드 주석·커밋 메시지·PR 설명 작성, 외부 공식 문서 조회, 스펙 기반 코드 생성, 코드 디버깅.

## 핵심 계약

- **진단 → 보고 → 승인 → 수정**: 기존 문서를 고치기 전에 불일치(변경)/누락(신규)을 구분한 진단 표를 근거(파일:라인, 커밋)와 함께 보고하고, 승인받은 항목만 수정합니다. 신규 문서 1개 생성처럼 덮어쓰기 없는 작업은 바로 진행합니다.
- **근거 기반 작성**: 문서의 모든 명령·옵션·경로는 코드에서 직접 확인한 것만 싣고, 실행 가능한 예제는 실행해 검증합니다.
- **보고에 표 발췌**: 결과 보고에는 핵심 표(명령어 표 등)를 산문 요약 대신 그대로 발췌해 보여줍니다.

## 문서 규칙

- 마크다운 파일명은 영어(kebab-case), 본문은 한국어, UTF-8. 대상 프로젝트의 기존 관례가 다르면 그것을 따릅니다.
- 간결함 우선, 예제 중심. 명령·옵션이 여러 개면 마크다운 표로 정리하고, 함정·제약은 별도 주의사항 섹션에 목록으로 모읍니다.

## 문서 사이트

기본 프레임워크는 Starlight입니다. 신규 scaffold와 기존 사이트 통합을 지원하며, 빌드 검증 없이 완료를 선언하지 않습니다. 완료 보고에는 사이트 구조 트리와 용도별 실행 명령(dev/build/preview)을 포함합니다. 배포(CI) 설정은 기본 범위가 아닙니다.
