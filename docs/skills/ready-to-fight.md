# ready-to-fight

## 개요

주장과 계획을 일방적으로 평가하지 않고, 사용자와 AI가 가장 강한 반론과 근거를 한 번에 하나씩 주고받으며 결정 전에 맹점을 찾습니다.

## 사용 시점

- Deep Interview로 확정한 의사결정과 acceptance criteria를 다시 압박 검증할 때
- 서비스 기획의 사용자 문제, 성공 지표, 최신 시장·정책 근거를 따져볼 때
- FE·BE 설계의 인터페이스, 실패 경로, 테스트와 rollback 조건을 검증할 때
- 결론을 내리기 전에 반대 근거까지 확인하고 싶은 업무상 주장이나 계획이 있을 때

개인 경험이나 감정 지원, 트라우마, 의료·법률·재무 등 고위험 조언에는 자동으로 진입하지 않습니다. 이런 맥락에서 정면 검증이 필요하면 사용자가 명시적으로 요청해야 합니다. 명시 요청은 토론 형식에 대한 동의일 뿐, 사실 확인이나 전문가 검토 같은 안전 기준을 낮추지는 않습니다.

## 사용 예

```text
$ready-to-fight 경쟁사 세 곳이 이 기능을 제공하므로 우리도 다음 달에 출시해야 해. 출시 여부를 검증해줘.
```

자연어로 정면 검증을 요청해도 호출할 수 있습니다.

```text
이 API 변경안에서 놓친 실패 경로를 red team 방식으로 검증해줘.
```

검증할 주장 또는 산출물과 그 주장이 영향을 주는 결정 목표가 필요합니다. 둘 중 하나가 빠지면 스킬이 질문 하나로 보완합니다. 검증 가능한 업무 주장에는 암시적으로 시작할 수 있으며, 이때는 RTF 역할과 언제든 중단하거나 강도를 낮출 수 있다는 점을 먼저 알립니다.

## 핵심 흐름

1. 검증할 주장과 결정 목표를 한 문장으로 고정합니다.
2. 대상에 맞는 세 가지 필수 검토 범주를 공개합니다.
3. 가장 강한 반론 하나와 질문 하나를 제시합니다.
4. 사용자와 AI 양쪽의 출처·가정·불확실성·한계를 같은 기준으로 확인합니다.
5. 입장이 바뀔 때만 `유지`, `강화`, `약화`, `철회`, `미결` 중 하나로 변경 내용을 보여줍니다.
6. 결정에 중요한 미결이 없을 때만 검증 완료로 종합합니다.

| 대상 | 반드시 확인하는 세 범주 |
| --- | --- |
| Deep Interview | 의도·결정 일관성 / acceptance criteria·비목표 / 근거·출처와 반환 gate |
| 서비스 기획 | 사용자·문제·대안 / 성공·guardrail·실험 / 위험·제약과 최신 외부 근거 |
| FE·BE | 관찰 행동·인터페이스·데이터 불변식 / 실패·보안·성능·관측성 / 테스트·회귀·rollback |

서비스 기획에서 현재 시장·정책·가격·경쟁 서비스처럼 결정을 바꾸는 외부 사실은 공식·1차 출처부터 확인합니다. 직접 링크와 확인 시각, 반대 근거, 한계를 남기고 최종 종합 직전에 다시 확인합니다. 접근할 수 없거나 서로 충돌하는 근거는 현재 사실로 단정하지 않고 미결로 둡니다.

## 대화 통제와 안전 경계

- `중단`, `취소`, `그만`, `stop`이라고 하면 추가 반론이나 재개 권유 없이 즉시 끝냅니다.
- 공격받는 느낌, 불편함, 압도감, 강도 하향, 잠시 멈춤을 말하면 토론을 pause하고 영향 인정과 오해 바로잡기만 합니다.
- pause 뒤에는 사용자가 계속하겠다고 명시하고 강도까지 정해야 토론을 다시 시작합니다.
- AI의 반론·질문과 사용자 응답을 한 exchange로 보고, 새 근거·반례·가정이나 범위 수정·입장 변화가 없는 exchange가 두 번 연속되면 미결로 남깁니다. 중간에 진전이 생기면 횟수를 0으로 되돌립니다.
- Deep Interview의 의도·핵심 결정·acceptance criterion이 바뀌는 finding은 반론을 계속하지 않고 질문 하나만 반환해 Restate와 실행 승인을 다시 받습니다.
